# @schemastud/messages

## 0.2.0

### Minor Changes

- c4faed7: Package and host catalogs may carry translator notes: an optional `notes` map of `key → note` (each key in the catalog's `messages`; each note a non-empty string of at most 500 characters). `schemastud-messages collect` validates them and writes them to a sibling `payload.notes` in the collected artifact, never inside a `{default, owner}` entry. With no notes, the artifact and its digest are byte-identical to before. The runtime ignores notes.
- 5eb6a95: The root entry exports the Notice primitives: `Notice`, `notice`, `say`, `NoticeError` (`new NoticeError(notice, englishMessages)`; `.message` stays English), `isNoticeError` (a brand that holds across installed copies of the runtime, where `instanceof` does not) and `noticeOf(messages, failure, fallback)`, which returns a notice only when the reader's catalog owns its keys. `Messages` gains `has(key)`. `@schemastud/messages/react` exports `RichMessage` and `richMessage(messages, key, parts, { emphasis? })` for sentences whose parameters are React nodes. These replace the per-package `message-descriptor`/`rich-message` copies, which consumers delete at their repin; nothing is re-exported from `/react`. Also recorded here: `schemastud-message-ratchet` scanner 2 (frame-foundation 65, shipped without a changeset) counts notifier arguments, the returns of helpers called in a sink, constant lookups, mapped literals and opted-in error classes, and a baseline from another scanner fails with "scanner widened: re-measure with --write".
- 1164df1: `MessageProvider` accepts `value: ClientCatalog | null`. With `null` it re-provides the outer provider's options unchanged (the same object, so consumers don't re-render) and ignores its own `pseudo`, inheriting the outer setting; at the root, `null` behaves exactly like no provider. It always renders the same Provider element, so a host can render `<MessageProvider value={catalog ?? null}>` and keep one tree shape (and its state) when a page gains or loses a catalog, instead of switching between a fragment and a provider. Adds `jsdom` as a dev dependency for the remount test.
- e9b5f62: Add the shared message runtime and explicit catalog collector. ui now peer-requires @schemastud/messages; hosts must install and dedupe one copy before upgrading. Publish messages before or with ui. MoneyFormat.locale is optional: explicit locale → message locale → en-US; currency remains explicit.
- 5122d14: `schemastud-message-ratchet` scanner 3 also counts the string default of a parameter or destructured binding whose name reaches a display sink, in its own function or passed by name one hop into a component of the same file (`navLabel = 'Account'` rendered as `label={navLabel}`). The children of a `<style>` or `<script>` element are never counted. The `unscanned` list gains a default passed more than one hop or to a component in another file. A baseline measured by scanner 2 fails with "scanner widened: re-measure with --write" until it is re-measured.
- c99033c: Read shared UI and frame copy through package catalogs on the one messages peer. Preserve caller copy overrides, standalone English and explicit money currency/locale. Add a Node-only AST display-copy ratchet with read-only comparison and a baseline that may only fall. Hosts install/dedupe the released messages peer; data-only host baselines are wired after train-end publication.

  Expand display-position coverage to logical children, object defaults, message parameters, formatting helpers and DOM copy; refuse stale baselines and run the read-only comparison in CI. Translate complete picker, status, trend and money sentences. DateCell deliberately uses en-US without a message provider rather than the browser locale.

### Patch Changes

- 6854b29: The published declarations are two self-contained files again (`index.d.ts`, `react.d.ts`), with no hashed shared chunk. A consumer whose hook infers its return type from `useMessages` (`ReturnType<typeof useMessages<…>>`) can name `Messages` again, so its own declaration build no longer fails with TS2742.
- 653fafb: `schemastud-message-ratchet` never passes without measuring (frame-foundation 79). **The bin always runs:** the census moved to a side-effect-free module, `bin/ratchet-lib.mjs`, which `@schemastud/messages/ratchet` now exports; the bin is a thin entry that calls `runRatchet` unconditionally, with no entry-point guard, so a pnpm shell shim, an npm `.bin` link, a wrapper or a loader can no longer turn the gate into a silent exit 0. The bin name and the package exports are unchanged. **No silent pass:** a config with no packages, or with a package whose roots hold no source file the census reads (only excluded, `.d.ts` or non-source files), fails with `Nothing measured`, naming the config and every such package; before, such a package counted 0 and passed. CONFORM: a host that imports the census from the bin file imports `@schemastud/messages/ratchet` instead (importing the bin now runs the gate); a host config with an unreadable package now fails, and the fix is to point the package at its real sources or remove it from the config and the baseline together. This repo's own config dropped `@schemastud/_resources` (`_resources/types` holds only a `.d.ts`) from the config and the baseline for that reason.
- cdf41cb: The display-copy ratchet bin now runs when reached through a symlink: a pnpm host's `node_modules/@schemastud/messages` link or a `.bin` link. Its entry guard compared the link path with the real path, so `main()` never ran and every pnpm host's `lint:messages` passed vacuously. It now compares real paths; importing the module still runs nothing.
