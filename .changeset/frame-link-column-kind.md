A `link` list-column kind draws a cell as a link to a row field (frame-foundation 77). **New kind:** `link`, registered for `list-column` beside `text`, `badge`, `badges`, `number` and `date`, with one option `hrefKey` naming a ROW field. The cell text is the column's own value, rendered exactly as the `text` kind renders it (its `text` options apply). A site-relative href (one leading `/`) draws through the kit's `renderLink`, the router link the cards already take, so it opens in-app; with no `renderLink` it is a plain anchor. An absolute href, `//host` included, is a plain anchor. A null, absent or empty href, or an empty value, renders exactly as `text`. **Interface addition, the row reaching a kind cell:** a list cell's RJSF registry now carries `formContext: { row }`, so every `list-column` kind, frame's or a host's, can read the whole row as `props.registry.formContext.row`. It is additive: no option, no `widgetProps` or seam change. The one new export is `type LinkCellOptions` (the `link` kind's wire options, `hrefKey` over the `text` options) from `@schemastud/frame/wire`, beside the other cell option types; the main barrel is unchanged. `createFrameRegistry` registers `link` with the kit's `renderLink` after frame's built-ins and before the host's `widgets`, so a host that registers `link` for `list-column` still replaces frame's.
